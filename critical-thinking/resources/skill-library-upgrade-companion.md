## Framework

The source questionnaire has A1–A4, Q01–Q60 and X01–X10: 74 entries. It is a design framework, not a benchmark result or evidence of model equivalence.

## Review sequence

Read one complete skill and its necessary companions. Preserve the original. Record purpose, specialist detail, constraints, examples and dependencies. Audit each applicable framework entry. Define observable acceptance conditions before tailoring the revision. Write a complete candidate, then check for lost functionality and damaged correct content.

Execute only tests supported by the actual environment. Save the candidate, review, test record and next exact action so work can resume without inventing progress. Do not copy all 74 design questions into everyday runtime instructions.

## Distinct states

Prepared means the candidate and documented design review are ready; it does not establish behavioral validation. Not run means a test exists but was not executed. Passed selected tests requires named checks and actual recorded results. Compared means a real comparison exists, not that the candidate won.

A role-played reviewer is not an independent evaluator. A polished reference is not ground truth. Local arithmetic or file checks are not target-model behavioral tests.
