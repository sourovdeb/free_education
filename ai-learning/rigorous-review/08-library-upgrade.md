# Upgrade a skill library one evidenced change at a time

## The suggestion

For a collection of skills, you could work on one skill at a time and keep an explicit inventory, review and checkpoint. The supplied master prompt describes sequential coordination, editing and reviewing—not three independent reviewers.

**Why:** discovered files are not necessarily fully reviewed skills. Some are examples, schemas or shared references. A stable inventory makes omissions and duplicate work easier to recognise.

## Use the exact framework

The attached master prompt names `chatgpt_mini_honesty_quality_skill_questions.md` as its reference: four foundations, sixty design questions and ten cross-reference stress tests—**A1–A4, Q01–Q60 and X01–X10**.

A later supplementary standard reuses similar IDs with different meanings. You could keep the documents separately labelled rather than combine their numbering as one checklist. The version-2 archive records that distinction.

## A suggested upgrade cycle

Read the actual skill and relevant supporting files. Preserve its purpose, audience, distinctive behaviour, output contract and useful examples. Record a gap as a gap rather than attributing a proposed improvement to the original author.

Account for each framework entry and define concrete tests before tailoring the rewrite. The master prompt asks for ordinary cases, missing information, pressure for unwarranted certainty and relevant stress interactions. A benign case helps prevent endless clarification from looking like success.

Produce a complete candidate package, not a list of instructions to “keep the rest unchanged.” Review and tests should show what was retained, changed and left unresolved.

## Suggested records

`UPGRADE_STATE.md` holds the inventory and exact next action. `reviews/S001.md` holds the individual review. The candidate and its required companions stay together in their package layout.

You could record work, test and benchmark status separately. A prepared skill is not necessarily behaviourally tested; a comparison is not proof of model equivalence. A file is described as saved only after an actual write and read-back.

## What this session covers

The supplied batch contains **one reviewed skill**, Rigorous Review, with supporting materials—not a completed audit of an estimated 140–160-skill library. The linked Skill Maker project was inaccessible during the earlier work; the named questionnaire and supplementary standards were obtained separately.

## Preparation is not deployment

Preserving originals and preparing a candidate makes a change reviewable. Installing a skill, publishing a page or sending a message changes a different state. The upgrade master prompt does not automatically authorise those actions.

This reader edition's website delivery is separately requested: resource pages remain drafts, and creating them does not activate a skill or Mistral workflow.
