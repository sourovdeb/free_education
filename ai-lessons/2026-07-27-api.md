## 📖 WHAT IS AN API?

**Simple Definition:**
An API (Application Programming Interface) is the messenger that lets your app talk to AI. It's the standardized way applications send requests to AI and receive responses.

**The Basic Rule:**
- You can't plug an app directly into an AI model
- APIs are the middleman that connects them
- APIs follow strict rules about how to send requests and receive responses
- Every request goes through the API, every response comes back through the API
- APIs handle authentication (are you allowed to use this?), rate limiting (don't overwhelm the system), and billing (how much did this cost?)

**Key Analogy:**
- Without API: You trying to call a store directly (impossible)
- With API: You call the store's phone line (standardized interface)
- Store says: "For orders, press 1. For returns, press 2." (Structured format)
- You give your order, they confirm it, you get your answer (predictable exchange)

**Why does this matter?**
Because without APIs, every app would need its own custom way to talk to AI. APIs standardize this so any app can talk to any AI model through the same interface.

**The Hidden Truth (What AI Companies Don't Explain Well):**
APIs are what monetize AI. Mistral gives you API access, and you pay per request. The console (web interface) is free, but when you build an app using the API, you pay. This is why companies care about API security—each request is a charge. APIs also handle rate limiting: if you send 1,000 requests per second, they'll reject the extras to protect their infrastructure.

## ⚙️ HOW DOES IT WORK?

### The Mechanism (Behind the Scenes)

**How an API request works:**

```
Step 1: Your App Prepares Request
Your code: "I want to chat with AI using mistral-large model"
Request format: {
  "model": "mistral-large",
  "messages": [
    {"role": "user", "content": "What is AI?"}
  ],
  "temperature": 0.7
}

Step 2: Request Sent to API
Your app sends HTTP POST request to:
https://api.mistral.ai/v1/chat/completions

Step 3: Authentication Check
API checks: "Does this API key exist? Is it active? Is it allowed?"
Header: Authorization: Bearer sk-xxx...xxx

Step 4: Rate Limiting Check
API checks: "How many requests has this key sent today?"
If over limit: Request rejected
If under limit: Continue

Step 5: Model Processing
Request sent to the AI model
Model processes: "What is AI?"
Model generates: "Artificial Intelligence is..."

Step 6: Response Created
Response: {
  "model": "mistral-large",
  "message": {
    "role": "assistant",
    "content": "Artificial Intelligence is..."
  },
  "usage": {
    "input_tokens": 15,
    "output_tokens": 120,
    "total_tokens": 135
  }
}

Step 7: Response Sent Back
API sends response to your app

Step 8: Your App Receives Response
Your app uses the AI response
Shows to user or processes it further

Step 9: Billing
API logs: "This request used 135 tokens"
At $0.27 per 1M tokens: cost = $0.000036
Charges to your account
```

### Real Example: Building a Chatbot

```
BACKEND CODE (Python):

import requests

response = requests.post(
    "https://api.mistral.ai/v1/chat/completions",

## 🎯 WHY SHOULD YOU CARE?

### Problem 1: Without API, You Can't Build Apps

The Mistral console is fun for experimenting, but you can't build a commercial app using it.

**Solution:** API lets you programmatically access AI from your code.

### Problem 2: APIs Cost Money

Every API request costs money. The console is free (it's just testing), but your app that uses the API will be charged.

**Impact:** You need to understand API usage to manage costs.

**Example:**
- Support chatbot with 1,000 users
- Each user sends 10 messages per day
- 10,000 requests per day
- At standard rates: ~$0.03 per day
- Over a year: ~$10/year
- Scale to 100,000 users: $1,000/year

### Problem 3: APIs Have Limits (Rate Limiting)

You can't send infinite requests. Mistral limits how many requests you can make.

**Example rate limits:**
- Starter plan: 1,000 requests/hour
- Professional plan: 100,000 requests/hour

If you exceed limits:
- Additional requests rejected
- Error message: "Rate limit exceeded"
- Your app breaks if it doesn't handle this

### Problem 4: APIs Require Authentication

You need an API key to access the AI model. If someone steals your key:
- They can use all your credits
- They can see your requests
- You need to regenerate the key immediately

### Problem 5: Debugging is Harder

With the console, you immediately see what the AI is doing. With APIs, you only see what your code tells you to see.

**Example problem:**
- Your app works in development
- In production, suddenly fails
- Was it an API issue? Your code? Rate limiting?
- Takes time to debug

# API: How Apps Talk to AI

## The Quick Answer

**An API** (Application Programming Interface) is the standardized messenger that lets your app communicate with AI models.

Think of it this way:

- **Console** = Calling the restaurant directly to chat with the chef
- **API** = Calling the restaurant's phone line where you place an order following their system

Same restaurant. Different interface. Different purpose.

## Why This Matters

The Mistral console is great for experimenting, but it's not a production tool. When you build a real application, you need the API.

The API is how:
- Web apps talk to AI
- Mobile apps talk to AI
- Backend services talk to AI
- Chatbots talk to AI
- Anything talks to AI

Without it, you're stuck in the console.

## What Is an API?

An API is a standardized interface for communication.

**Example:**
```
Your App → HTTP Request → Mistral API → AI Model
                ↓
            Processing
                ↓
AI Response → HTTP Response → Your App
```

That's it. Your app makes a structured request, the API processes it, you get a structured response back.

## Why APIs Instead of Direct Connection?

### Reason 1: Standardization
- All apps use the same format
- Everyone follows the same rules
- Mistral can build one API instead of individual connections for every developer

### Reason 2: Security
- API key authentication
- Prevents unauthorized access
- Can revoke keys immediately
- Audit trail of who accessed what

### Reason 3: Rate Limiting
- Prevents system overload
- Each developer gets fair access
- If one person sends 10,000 requests/sec, others still work

### Reason 4: Billing
- Each request is tracked
- Can bill accurately for usage
- Shows cost per request

## How APIs Work

### Step-by-Step Request

```
1. Your Code Prepares Request

const payload = {
  model: "mistral-large",
  messages: [
    { role: "user", content: "What is AI?" }
  ],
  temperature: 0.7
};

2. Send to API Endpoint

POST https://api.mistral.ai/v1/chat/completions
Authorization: Bearer sk-your-api-key
Content-Type: application/json

{...payload...}

3. API Validates Request
- Is the API key valid?
- Are parameters correct?
- Is the user under rate limits?

4. API Sends to Model
Request processed by mistral-large

5. Model Generates Response
"Artificial Intelligence is..."

6. API Formats Response

{
  model: "mistral-large",
  choices: [{
    message: {
      role: "assistant",
      content: "AI is..."
    }
  }],
  usage: {
    input_tokens: 15,
    output_tokens: 120,
    total_tokens: 135
  }
}

7. Response Sent Back to Your App

8. Billing
Your account charged for 135 tokens used
```

## Real Example: Building a Chatbot

Here's what the code looks like:

```python
import requests
import os

API_KEY = os.environ.get("MISTRAL_API_KEY")
API_URL = "https://api.mistral.ai/v1/chat/completions"

def chat_with_ai(user_message):
    response = requests.post(
        API_URL,
        headers={
            "Authorization": f"Bearer {API_KEY}",
            "Content-Type": "application/json"
        },
        json={
            "model": "mistral-large",
            "messages": [
                {"role": "user", "content": user_message}
            ],
            "temperature": 0.7
        }
    )
    
    if response.status_code == 200:
        data = response.json()
        ai_response = data["choices"][0]["message"]["content"]
        tokens_used = data["usage"]["total_tokens"]
        return ai_response, tokens_used
    else:
        return "Error: API request failed", 0

# Usage
response, cost = chat_with_ai("Hello AI!")
print(response)
```

That's it. That's how apps talk to AI.

## Pricing Model

### How Billing Works

Mistral charges per token (not per request):

```
Input tokens: $0.27 per 1M tokens (what you send)
Output tokens: $0.81 per 1M tokens (what AI generates)

Example:
Request: "Hello" = 2 input tokens
Response: "Hi there, how are you?" = 7 output tokens
Cost: (2 * 0.27 + 7 * 0.81) / 1,000,000 = $0.0000063
```

### Cost Example: Support Chatbot

```
Scenario: 1,000 users, each sends 10 messages/day

Calculation:
- 10,000 messages/day
- Avg 50 tokens per message (input + output)
- 500,000 tokens/day
- At standard rates: ~$0.27/day
- Monthly: ~$8
- Yearly: ~$96
```

Scale to 100,000 users: ~$9,600/year

## Rate Limits

APIs limit how fast you can send requests:

```
Starter: 1,000 requests/hour
Professional: 100,000 requests/hour
Enterprise: Custom limits
```

If you exceed limits:
```json
{
  "error": {
    "message": "Rate limit exceeded",
    "type": "rate_limit_error"
  }
}
```

Your app needs to handle this gracefully.

## Security Best Practices

### 1. Protect Your API Key
```python
# WRONG
api_key = "sk-xxx-xxx"  # Hardcoded!

# RIGHT
api_key = os.environ.get("MISTRAL_API_KEY")  # Environment variable
```

### 2. Never Commit Keys to GitHub
Add to .gitignore:
```
.env
*.key
secrets.json
```

### 3. Use Environment Variables
```bash
export MISTRAL_API_KEY="sk-xxx-xxx"
python app.py
```

### 4. Regenerate If Compromised
- If key is leaked: Regenerate immediately
- Old key becomes invalid
- Only takes 5 seconds

### 5. Monitor Usage
- Check dashboard daily
- Set up billing alerts
- Unusual spike = Someone might have stolen your key

## Common Mistakes

❌ **Committing API keys to GitHub** → Hackers steal it, run up your bill

❌ **Ignoring rate limits** → App breaks under load

❌ **Not handling errors** → API fails, app crashes

❌ **No retry logic** → Temporary network issue kills your request

❌ **Not caching responses** → Paying twice for the same answer

❌ **Logging API keys** → Logs get compromised, key is exposed

## Pro Tips

**Tip 1:** Cache common responses
```python
cache = {}
if question in cache:
    return cache[question]  # Free!
else:
    response = call_api(question)
    cache[question] = response
    return response
```

**Tip 2:** Implement retry logic
```python
for attempt in range(3):
    try:
        return api_request()
    except:
        time.sleep(2 ** attempt)  # Exponential backoff
```

**Tip 3:** Set timeouts
```python
response = requests.post(..., timeout=30)  # Don't wait forever
```

**Tip 4:** Batch requests
```python
# Instead of 100 separate API calls
# Send 1 request with 100 prompts
# Much faster, more efficient
```

**Tip 5:** Use streaming for long responses
```python
# Instead of waiting for full response
# Get response character by character
# User sees text appearing in real-time
```
